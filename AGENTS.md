# SiteAR

Native iOS 17+ app (SwiftUI, ARKit, RealityKit) with a Supabase backend. DHBW course project by Leonard Aichele and David Westhauser.

## Start here
- `docs/STATUS.md`: what works and what is missing now.
- `docs/tickets/README.md`: ticket index and suggested order. `docs/README.md` indexes the other docs (requirements, architecture, backend setup, device testing).

## Commands
- Core tests: `swift test`
- App and UI tests: `xcodebuild -project SiteAR.xcodeproj -scheme SiteAR -destination 'platform=iOS Simulator,name=iPhone 17' test`
- Format and lint (must be clean before committing): `swift format --in-place --recursive SiteAR SiteARTests SiteARAppTests SiteARUITests Package.swift`, then the same with `lint --strict` instead of `--in-place`. Rules: `docs/CONVENTIONS.md`.
- RLS tests: `supabase start && supabase db reset && supabase test db`
- The Xcode project is generated by `scripts/generate_project.py`. Change the script and regenerate instead of hand-editing `project.pbxproj`.

## Workflow
- Work from a ticket. When done, tick its acceptance criteria, set `Status: done`, and update the ticket index and `docs/STATUS.md`.
- Small commits with the ticket ID (`T-005: ...`). Both team members need regular commits, so avoid large mixed commits.
- When a doc is outdated, replace the text instead of appending to it.

## Gotchas
- The app is SiteAR, but some identifiers keep the old name for compatibility. Do not rename: bundle ID `de.davidwesthauser.sitescope`, AR anchor `sitescope.room.<id>`, local data folder `sitescope/`, Keychain service `sitescope.auth`, the `.sitescope` file type. The archive magic must stay exactly 8 bytes (`SiteAR01`).
- Never commit `SiteAR/Resources/Secrets.xcconfig` (copy `Secrets.example.xcconfig`). Only the publishable Supabase key goes in the app.
- Enforce access control with RLS on the server, not only in the UI.
- Keep pure logic in `SiteAR/Core/`, covered by unit tests.
- AR behaviour can only be verified on a real iPhone (`docs/DEVICE_TESTING.md`). Do not report AR as working based on simulator runs.
