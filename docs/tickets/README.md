# Tickets

One file per work item, `T-XXX-short-name.md`, in the folder that matches its status:

| Folder | Holds |
|---|---|
| `todo/` | Not started (or `blocked`) |
| `in-progress/` | Someone is working on it |
| `done/` | All acceptance criteria ticked and STATUS.md updated |

**Do not move files by hand.** Change the ticket's `Status:` line, then run `python3 scripts/tickets.py`. It moves the file, fixes links and regenerates the index below. `--check` only reports what is out of date.

**Size:** a ticket is one PR by one person, about 2–6 h, and lists its own tests in the acceptance criteria. Larger work is an *epic* (`T-008`) with sub-tickets (`T-008a`, `T-008b`, …); the epic is done when all sub-tickets are. Write tests only for features that exist: a test for an unfinished feature belongs in a ticket that depends on that feature.

**Priority:** P0 = project MUST-HAVE feature or blocks other work · P1 = general MUST-HAVE and grading quality (tests, architecture, error handling, docs) · P2 = polish of existing features · P3 = NICE-TO-HAVE. Requirement IDs refer to [REQUIREMENTS.md](../REQUIREMENTS.md).

Budget: ~160 h for two people. Open estimates add up to about 175 h, so P0/P1 come first and P3 (NICE) only if time remains. NICE-TO-HAVEs count only with ≥ 40/50 MUST points.

## New ticket template

Create it in `todo/`, then run the script. `python3 scripts/tickets.py --lint` checks every ticket against this template. An epic replaces `## Tasks` with `## Sub-tickets` (a list of links). An optional `## Notes` section may come last.

```markdown
# T-XXX Title

- Status: todo · Priority: Px · Estimate: N h · Owner: — · Depends on: —
- Requirements: Mx, Gx

## Goal

One or two sentences: what changes for the user or the code, and why.

## Tasks

- [ ] ...

## Acceptance criteria

- [ ] ... (including the automated test)
```
